# Comms-01 migration prerequisites

These steps are an out-of-band, root-owned bootstrap for the isolated
Comms-01 control database. They are not executable from Manager, Executor,
Auditor, Terra, or a runtime database role.

The operator must independently verify the database name, local PostgreSQL
socket/port `5432`, cluster identity, and the exact host before running them.

```sql
-- Run as the pinned local PostgreSQL administrator on the verified target.
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
GRANT USAGE, CREATE ON SCHEMA public TO top_delivery_migration;

-- The migration role is a non-login, non-superuser owner. Runtime roles must
-- never be members of one another or of the migration role.
ALTER ROLE top_delivery_migration NOLOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT;
REVOKE top_delivery_authority FROM top_delivery_workflow;
REVOKE top_delivery_workflow FROM top_delivery_authority;
REVOKE top_delivery_migration FROM top_delivery_workflow;
REVOKE top_delivery_migration FROM top_delivery_authority;
```

Required verification before a migration:

1. `top_delivery_migration` has `USAGE` and `CREATE` on `public`, and `PUBLIC`
   has no `CREATE` privilege.
2. `pg_auth_members` contains no direct or transitive membership involving
   the workflow, authority, migration, or disposable attacker roles.
3. The migration is entered through the pinned administrator and then
   `SET ROLE top_delivery_migration`; the session remains bound to that
   transport identity.
4. The migration head, source hashes, database identity, backup, and rollback
   evidence are recorded before any schema mutation.

Before the first migration, run the explicit namespace bootstrap as the pinned
local administrator. This is an operator/bootstrap action, not an Alembic
revision and not a workflow-role capability:

```bash
PYTHONPATH=controller python -m migration_bootstrap \
  --database-url 'postgresql://root@/top_delivery_control_p1?host=%2Fvar%2Frun%2Fpostgresql&port=5432'
```

The command creates or verifies `top_delivery_recovery`, revokes runtime and
PUBLIC access, and provisions `alembic_version` ownership when that metadata
table already exists. `controller/migrations/env.py` only verifies those
objects and fails closed if the bootstrap was omitted or drifted.

Also install the reviewed 008 source digest as a separate root-owned, mode
0600 trust file before any 008 upgrade. The file is not generated by Alembic
or the workflow:

`/etc/top-delivery/comms01-migration-source-provenance.json`

```json
{
  "algorithm": "sha256",
  "normalization_version": 1,
  "revision": "008_longspan_authority_repair",
  "source_digest": "<digest from the reviewed release manifest>"
}
```

008 checks both its diagnostic self-marker and this independent anchor before
executing migration DDL.

If an existing disposable 007 database has the right object names but an
unexpected owner, 008 deliberately rejects it. Ownership repair is an
operator-controlled prerequisite, not a migration side effect. On the pinned
administrator connection, inspect the exact rows first:

```sql
SELECT n.nspname, c.relname, c.relkind, pg_get_userbyid(c.relowner)
FROM pg_class AS c
JOIN pg_namespace AS n ON n.oid = c.relnamespace
WHERE n.nspname = 'public'
  AND c.relname IN ('controller_control', 'supervisor_runs',
                    'parent_tasks', 'task_attempts', 'retry_queue',
                    'supervisor_events', 'evidence_index',
                    'manifest_submissions', 'required_manifest_entries',
                    'signal_status', 'provenance_records', 'notifications',
                    'alembic_version', 'top_delivery_downgrade_capabilities',
                    'longspan_children', 'longspan_plans',
                    'longspan_execution_results', 'longspan_auditor_receipts',
                    'longspan_terra_receipts', 'longspan_experiments',
                    'longspan_evidence_ledger', 'longspan_authority_config',
                    'longspan_authority_history', 'longspan_operator_challenges',
                    'longspan_authority_receipts',
                    'longspan_terra_receipt_attestations',
                    'longspan_execution_audits', 'longspan_execution_evidence',
                    'longspan_ledger_legacy_attestations', 'longspan_mac_material',
                    'longspan_mac_key_history')
ORDER BY c.relname;
```

Only after the result is reconciled against the reviewed catalog may the
pinned administrator run explicit `ALTER TABLE public.<verified_name> OWNER
TO top_delivery_migration`, `ALTER SEQUENCE public.<verified_name> OWNER TO
top_delivery_migration`, or `ALTER FUNCTION public.<verified_signature> OWNER
TO top_delivery_migration` statements for the returned, reviewed objects.
Re-run the inventory and record its output before retrying 008. Never use a
wildcard ownership loop and never grant a runtime role membership to make the
repair work.

If any prerequisite is not true, stop the migration and repair it with the
cluster administrator. No application or workflow role may self-authorize the
repair.
